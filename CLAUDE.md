# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

A `~/.config` dotfiles repo for a **Niri-based Wayland Linux desktop** (Arch Linux). Changes here are applied to a real machine — keep edits minimal, safe, and reviewable.

## Commands

- **Fetch wallpapers submodule:** `git submodule update --init --recursive`
- **Syntax-check scripts:** `bash -n scripts/*.sh` (or `shellcheck scripts/*.sh`)
- **Neovim health:** `nvim --headless "+checkhealth" +qa`
- **Neovim plugin sync:** open `nvim`, run `:Lazy sync`
- **Format Lua (nvim):** `stylua nvim/` (2-space indent, 120 cols — see `nvim/stylua.toml`)

## Architecture

### Theming Pipeline (the core system)

Wallpaper selection drives system-wide theming:

1. User picks wallpaper via `scripts/bgselector.sh` (rofi UI) → `awww` sets it
2. `scripts/theme-sync.sh` (736 lines, the orchestrator) detects theme from wallpaper path
3. `wallust` extracts colors from the wallpaper → writes `~/.cache/wallust/colors.json`
4. Wallust templates (`wallust/templates/`) generate per-app color configs (20+ targets: waybar, rofi, mako, terminals, gtk, spicetify, etc.)
5. `theme-sync.sh` also updates GTK settings, niri border colors, xsettingsd, and sends reload signals (HUP, USR2, dbus)

Eight themes supported (catppuccin, dracula, everforest, gruvbox, material, nord, rose-pine, solarized, tokyo-night), each with light/dark variants. Theme→GTK/icon/wallust mappings are defined in `scripts/theme-sync.sh` lines 62-289.

### Key Directories

- **`niri/`** — Window manager config (KDL). `config.kdl` has keybindings, window rules, startup commands
- **`scripts/`** — Bash automation. `lib/common.sh` has shared logging/validation. `theme-sync.sh` is the big one; `media-control.sh` handles volume/brightness/playerctl
- **`wallust/`** — Color generation config (`wallust.toml`: fastresize backend, harddark palette, LAB color space) and templates
- **`nvim/`** — LazyVim setup. See `nvim/AGENTS.md` for nvim-specific guidelines
- **`fish/`** — Fish shell. `config.fish` has aliases, custom functions, PATH setup. `conf.d/` for per-tool fragments
- **`waybar/`** — Vertical left-side status bar. `modules.json` for module defs, `colors.css` generated by wallust
- **`rofi/`** — App launcher. `colors/wallust.rasi` generated by wallust

### Neovim (nvim/)

LazyVim framework with lazy.nvim. One-concern-per-file plugin specs in `lua/plugins/`. Uses `opts = function(_, opts)` pattern for clean merges with LazyVim defaults. Has its own `AGENTS.md` with detailed conventions.

## Style

- **Commits:** Conventional Commits — `feat:`, `fix:`, `chore:`, `refactor(scope):`, `test:`
- **Lua:** StyLua with `nvim/stylua.toml` (2-space indent, 120 cols)
- **Shell:** Bash with `set -euo pipefail`; use `scripts/lib/common.sh` for logging/validation
- **Configs:** Keep idiomatic to the target tool — don't normalize formatting across different apps
- **Paths:** Align with upstream app names (`niri/`, `nvim/`, `waybar/`); don't add new top-level dirs without a clear owner

## Important Notes

- Many app directories are git-ignored (browsers, IDEs, caches). Check `.gitignore` before adding new paths.
- `wallpapers/` is a git submodule, not a regular directory.
- No secrets in this repo. `*.env` is ignored; use placeholders if env vars are needed.
- No automated test suite. Validate by reloading/restarting the affected app and checking for errors.
